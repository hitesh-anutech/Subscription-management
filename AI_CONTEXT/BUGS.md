## Non-bugs / Operational Gotchas (not code defects)
- **App-generated quote PDF embeds PNG/JPEG logos only (pdf-lib limit, 2026-07-18).** The SendGrid quick-quote email attachment + branding on it are drawn with **pdf-lib**, which can't embed **SVG or WebP** — an SVG/WebP logo/signature is silently skipped in that PDF. It also uses the **ISO currency code** (not the ₹/symbol — not WinAnsi-encodable in Helvetica) and **strips non-Latin-1 text** (e.g. Hindi/Devanagari) from the PDF. The `/quotes/[id]/print` page uses `<img>`/HTML, so it renders SVG/WebP/₹/Hindi fine. Fix for a faithful generated PDF: upload PNG/JPG logos, or embed a Unicode font + rasterize SVG (deferred). Not a defect.
- **Zoho-sent emails already attach the doc PDF natively** — the "attach related Quote/Invoice" request (2026-07-18) only added an attachment to the **SendGrid quick-quote** send; the Zoho invoice/quote/batch emails were intentionally left unchanged (adding our own would duplicate).
- **2026-07-16 status:** the **bulk-domains fresh flow was live-verified by the user** (quote → accept → convert → INV-000048 → auto subscriptions). Still unverified live: **≥100-domain annexure on an invoice**, the **per-customer "Generate Bulk Quotes" grouping** (mixed items → one combined estimate), the **"बाद में" decision + "Create N Subscriptions" re-run (dedup)**, and the bulk line's email/public/print display.
- **Bulk subscription create needs cache-selected items.** `bulk-create-from-quote` skips (with a per-line error) any quote line without a `zohoItemId` (manually typed item names) or without a Subs. Period — pick items from the Zoho cache search when building bulk-domain quotes.
- **2026-07-15 sales-flow pass is unverified against live Zoho.** The Customers browser, the redesigned Quick Quote Unified Builder (incl. unified Lead+Quote create), and the Convert/Push domain+dates flow are all typecheck-clean (both apps, exit 0) but have not been driven against a live Zoho-connected org. Treat as unverified until UAT.
- **Customers browser inherits the Zoho-cache limits.** Custom-field + rich columns only populate for customers whose detail was fetched into `zoho_cache.extra` (bulk `syncCustomers` stores only LIST-level fields — no `billing_address`/`contact_persons`/`custom_fields`). Columns scanned from `extra` therefore reflect what's actually cached, not the full Zoho contact.
- **Batch review screen & Quotes & Invoices browser are unverified against live Zoho** (2026-07-14). Both are typecheck-clean and mirror live-verified code paths (per-row `sendProforma`/`refreshProformaStatus`; the import fetch layer), but neither has been driven against a live Zoho-connected org. Treat as unverified until UAT.
- **Quotes & Invoices browser is API-call-heavy.** One Zoho detail call per row, plus one more per row that has a linked invoice/quote (cross-link columns). A 100-row page of fully-converted docs ≈ up to ~200 Zoho calls — can be slow / risk rate limits. Prefer 25–50/page. Not a defect; a known cost of the live-fetch design.
- **Batch bulk-send has no per-recipient review.** "Send Selected / Send All" send with Zoho's **default** email template (recipient from the template) with no compose step — by design (bulk). Use the per-row **✉ Send** compose modal when you need to edit To/CC/subject/body.

## Non-bugs / Operational Gotchas — earlier
- **Combined Quote with multiple ≥100-domain lines** attaches multiple annexure PDFs to the single estimate (one per large line group, distinct filenames). Assumed fine (Zoho supports multiple attachments); unverified live. Single large line is the common case.
- **Combined Quote RenewalBatch summary columns are representative, not aggregate.** For a combined batch, `zohoItemId`/`billingCycle`/`unitPrice` hold the header sub's values and `zohoItemName` reads `"Combined Quote (N lines · M domains)"`; the true per-domain breakdown is in `annexureData` and the linked `renewal_history` rows. Don't treat those scalar columns as authoritative for combined batches.
- **Import error "Item ID/SKU … not found in Zoho cache"** — the org's **items** haven't been synced into `zoho_cache` (customers can be synced without items). Fix: Settings → Organizations → **Sync** for that org, then retry. Confirmed 2026-07-10: dev DB's Excel Technologies org had 1238 customers but 0 items.
- **`prisma generate` `EPERM` on the query-engine `.dll`** while dev servers run (Windows file lock). The TypeScript types still regenerate; the engine binary refreshes on server restart. Use `db push --skip-generate`.
- **Org custom-field metadata is rewritten by re-sync.** During the 2026-07-11 session, `org_settings.metadata.billing_period_options` for AntuTech Digital (org `60069493045`) was populated, then became `[]` between two checks, and `custom_field_mappings.estimates` grew from 3 → 5 rows — all without code changes, i.e. the org was re-synced/reconfigured. **Implication:** don't rely on any single option list always being present. `bulkRenewalQuote` now uses a static Subs Period fallback so it's resilient. If a dropdown custom field shows blank on a generated doc, first check whether that option list is empty and re-sync the org.
